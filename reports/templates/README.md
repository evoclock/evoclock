# Report Templates

Reusable HTML templates for public benchmark reports. Generated reports should
stay self-contained so they can be published as GitHub gists and viewed through
htmlpreview without relying on repo-relative CSS or JavaScript.

## Power Station Report

Use `powerstation-report.html` for evaluation writeups with tables and
expandable per-model evidence cards.

Palette source: `thermall-power-station` from `/home/julen_gamboa/thermall`.

Style reference: the nuthatch KB demo graph uses the same Power Station chrome
with floating panels, compact chips, muted borders, green labels, and orange
focus accents. Keep benchmark reports in that family: dark warm graphite,
cream text, restrained tables, and evidence cards that expand in place.

## Workflow

The benchmark repo remains the source of truth. If `/home/julen_gamboa/ai-models/`
contains a report, treat that report and its data as canonical. This repo is the
GitHub-facing presentation layer: copy or transform the relevant report into the
Power Station template here, review the narrative and evidence cards, then publish
the resulting self-contained HTML as a gist/htmlpreview link.

Keep generated adaptation outputs under `reports/output/`, which is ignored. Only
commit reusable templates, small render/adaptation scripts, and README-facing
assets or links.

## Report Shape

Recommended order:

1. Claim title and one-sentence finding.
2. Benchmark/task definition, with jargon defined before use.
3. Setup and methodology, clearly separating measurement fixes from
   model-facing interventions.
4. Score table.
5. Grouped interpretation.
6. Definitions.
7. Narrative bridge into expandable per-model evidence cards.
8. Caveats and next experiment.

The expandable cards should be part of the argument. They are the audit trail
for the aggregate claim, not an appendix pasted below the report.

## Rendering

For a new report, create a small JSON metadata file and render the template:

```bash
python3 reports/scripts/render_powerstation_report.py metadata.json output/report.html
```

The renderer fills only the shared top-level placeholders. Benchmark-specific
score rows and evidence cards should still be generated by the benchmark's own
script, then inserted into the same template structure.
